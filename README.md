# Bit-Brain AI — Offline Bitcoin Forensic Intelligence Platform

SIH 2026 · Problem Statement SIH26146 · Team Bit Brainers

A fully offline pipeline that ingests bulk Bitcoin network + blockchain metadata,
builds an address–transaction graph, clusters addresses into entities, scores
each entity with a hybrid Isolation Forest + Random Forest model, explains every
flag with SHAP, and surfaces ranked leads with evidence in a dashboard.

## What's real vs. synthetic in this build

- **Blockchain layer (addresses, transactions)** and **network layer (IP/port/broadcast
  timestamp)** are generated by `data/generate_synthetic_data.py`. Public forensic
  datasets (Elliptic++) provide labeled blockchain data but not packet-level network
  metadata joined to txids — that pairing doesn't exist publicly, so it's synthesized
  here with documented, injected fraud patterns (fan-out, shared-IP mixer clusters,
  bursty timing). See `docs/technical-writeup.md` for the full rationale.
- **To use real data**: drop your own CSVs into `data/raw/` matching the schema in
  `pipeline/ingest.py` (or point `ingest.py` at Elliptic++ directly) and skip the
  generator step.
- Everything downstream (graph, features, models, API, dashboard) works identically
  regardless of where the data came from.

## Environment variables

Every configurable value lives in `config.py` (pipeline + backend) and is read from
environment variables with a working default — nothing is required to get started.
Copy the templates before customizing:

```bash
cp .env.example .env                    # backend + pipeline config, read by docker-compose
cp frontend/.env.example frontend/.env  # frontend build-time config (npm run dev / build only)
```

| Variable | Default | Used by | Purpose |
|---|---|---|---|
| `DATABASE_PATH` | `./bitbrain.db` (`/app/bitbrain.db` in Docker) | pipeline, backend | SQLite file location |
| `GRAPH_PATH` | `pipeline/graph.gpickle` | pipeline, backend | NetworkX graph pickle location |
| `MODEL_DIR` | `pipeline/models` | pipeline, backend | trained model (`.joblib`) storage |
| `FEATURES_PATH` | `pipeline/features.csv` | pipeline | computed feature table |
| `RAW_DATA_DIR` | `data/raw` | pipeline | raw CSV input directory |
| `METRICS_PATH` | `docs/model_metrics.json` | pipeline | holdout precision/recall/AUC output |
| `BACKEND_HOST` | `0.0.0.0` | backend | bind address |
| `BACKEND_PORT` | `8000` | backend, docker-compose | API port (host + container in Docker) |
| `CORS_ORIGINS` | `*` | backend | comma-separated allowed origins, e.g. `http://localhost:8080,http://192.168.1.50:8080` |
| `LOG_LEVEL` | `info` | backend | uvicorn log verbosity |
| `FRONTEND_PORT` | `8080` | docker-compose | dashboard's host port |

Frontend-only (`frontend/.env`, baked into the bundle at build time by Vite):

| Variable | Default | Purpose |
|---|---|---|
| `VITE_API_BASE_URL` | `/api` | base path the dashboard calls for the API |
| `VITE_RISK_TIER_HIGH` | `70` | must match `RISK_TIER_HIGH` — controls badge color only |

**Docker note**: `DATABASE_PATH`, `GRAPH_PATH`, `MODEL_DIR`, `FEATURES_PATH`, `RAW_DATA_DIR`,
`METRICS_PATH`, and the `SYNTH_*` vars are consumed at **both** image build time (so the
pipeline writes to the right place) and container runtime (so the API reads from the same
place) — `docker-compose.yml` passes your `.env` values to both automatically, so you never
need to edit the Dockerfiles or compose file directly.

## Setup — Docker (recommended, fully offline after first build)

**Prerequisites**: Docker Desktop (Windows/Mac) or Docker Engine + Compose plugin (Linux).

1. **Extract the project** to a folder — make sure you land directly inside the folder that
   contains `docker-compose.yml`, not a doubly-nested `bit-brain-ai/bit-brain-ai/`.
   ```bash
   cd path/to/bit-brain-ai   # this folder should directly contain docker-compose.yml
   ls docker-compose.yml     # confirms you're in the right place
   ```
2. **(Optional) configure environment**:
   ```bash
   cp .env.example .env
   # edit .env if you want non-default ports, CORS origins, risk weights, etc.
   ```
3. **Build and start both containers**:
   ```bash
   docker-compose up --build
   ```
   First build takes a few minutes (installs Python + Node deps, then runs the full
   offline pipeline — data generation, ingestion, graph build, feature engineering,
   model training — once, baked into the backend image).
4. **Open the dashboard**: http://localhost:8080 (or `$FRONTEND_PORT` if you changed it)
5. **API docs** (auto-generated): http://localhost:8000/docs
6. **Stop**: `Ctrl+C`, then `docker-compose down`
7. **Rebuild after any code or `.env` change**: `docker-compose up --build --force-recreate`

**Verifying it's truly offline**: disconnect your network, then `docker-compose up`
(without `--build`, since the images are already built) — the dashboard should come up
and function normally, since nothing at runtime makes an external call.

## Setup — manual (for active development, hot-reload)

**Prerequisites**: Python 3.11, Node.js 20+, both with internet access for this one-time
install step only.

1. **Clone/extract and enter the project folder** (same caveat as above — check
   `requirements.txt` is directly inside the folder you `cd`'d into).

2. **Python environment**:
   ```bash
   python3.11 -m venv .venv
   # Windows:  .venv\Scripts\activate
   # Linux/Mac: source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. **(Optional) set environment variables** for this shell session, or `cp .env.example .env`
   and use a tool like `python-dotenv`/your shell's `.env` loader — this project reads
   `os.environ` directly, so plain exports work too:
   ```bash
   # Linux/Mac
   export CORS_ORIGINS="http://localhost:5173"
   # Windows PowerShell
   $env:CORS_ORIGINS = "http://localhost:5173"
   ```

4. **Run the full pipeline** (generates data, builds the graph, trains models, populates
   the alerts table — takes under a minute):
   ```bash
   python pipeline/run_pipeline.py
   ```

5. **Start the API**:
   ```bash
   uvicorn backend.main:app --reload --port 8000
   ```
   Leave this terminal running. Confirm it's up: http://localhost:8000/api/overview

6. **In a second terminal, set up and start the frontend**:
   ```bash
   cd frontend
   cp .env.example .env     # optional, defaults work with the dev proxy
   npm install
   npm run dev
   ```

7. **Open the dashboard**: http://localhost:5173 (Vite's dev server proxies `/api` calls
   to `localhost:8000` automatically — see `vite.config.js`)

## Re-running individual pipeline stages

```bash
python data/generate_synthetic_data.py   # regenerate raw data/raw/*.csv
python pipeline/ingest.py                 # load raw/*.csv -> bitbrain.db
python pipeline/graph_builder.py           # build graph.gpickle + entity clusters
python pipeline/features.py                # compute pipeline/features.csv
python pipeline/train.py                   # train models, write docs/model_metrics.json,
                                            # populate the `alerts` table the API serves
```

## API summary

| Endpoint | Purpose |
|---|---|
| `GET /api/overview` | aggregate counts by risk tier |
| `GET /api/alerts?min_score=&status=&limit=` | ranked alert list |
| `GET /api/entities/{entity_id}` | full evidence bundle: score, SHAP drivers, timeline, addresses |
| `GET /api/graph/{entity_id}?hops=2` | k-hop evidence subgraph for visualization |
| `POST /api/feedback` | investigator marks an entity reviewed / flagged / safe |
| `GET /api/dataset/schema` | accepted formats and entity-clustering method |
| `POST /api/dataset/upload` | upload one CSV, JSON, or XML transaction file; replaces the current dataset and re-runs the full pipeline in the background |
| `GET /api/dataset/status` | poll upload/pipeline progress (`idle`\|`running`\|`done`\|`error`) |
| `GET /api/transactions/search?q=&limit=` | search transactions by txid or address substring, resolved back to entity + risk score where possible |
| `GET /api/transactions/{txid}` | single transaction detail |

### Uploading your own dataset

The dashboard's "Upload Dataset" page (or `POST /api/dataset/upload` directly)
accepts one `.csv`, `.json`, or `.xml` transaction file. The normalizer recognizes
common transaction fields such as `txid`/`hash`, `timestamp`/`time`,
`input_addresses`/`inputs`/`from`/`vin`, and
`output_addresses`/`outputs`/`to`/`vout`. Addresses co-spent as transaction inputs
are grouped into inferred entities; other addresses begin as individual entities.
The normalizer generates the internal entities, addresses, and transactions files,
so they do not need to be uploaded separately. Network-layer features are empty
unless supplied through a future correlated network-data import. Labels are inferred
as `unknown`; if there isn't enough labeled data to train a supervised model,
scoring falls back to Isolation-Forest-only anomaly detection. `docs/model_metrics.json`'s
`"mode"` field states which scoring path was used.

Uploading a new dataset **replaces the current one entirely** — it does not merge with
the existing demo data or a previous upload.

## Swapping in production-grade storage

This build uses SQLite + a NetworkX pickle to keep the offline footprint small and
the setup trivial for a hackathon demo. `pipeline/ingest.py` and `backend/main.py`
isolate all storage access, so swapping SQLite → PostgreSQL/TimescaleDB and the
graph pickle → Neo4j means changing the connection layer only — no changes to
feature engineering, models, or the API contract.
